An app event trigger runs your script when something happens in one of your connected apps. Instead of checking a tool yourself or starting a script by hand, you pick the event you care about — a new Slack message, a Calendly booking, an issue opened in Linear — and Script.it runs the script when it happens.

## Before you start

A trigger watches an account you've connected. The trigger list shows every event, including those for apps you haven't connected yet — they're marked **Connect to use**. Picking one opens the connection dialog, and you can carry on once you've connected.

You can also connect ahead of time from **Settings → Integrations**, or just ask the agent — it'll prompt you when a connection is missing. See [Connecting integrations](/integrations/connecting).

<Note>
  If the connection a trigger uses is removed or its access expires, the trigger pauses until you reconnect. Then it resumes on its own. See [Triggers that pause themselves](/triggers/managing#triggers-that-pause-themselves).
</Note>

## Creating an app event trigger

<Steps>
  <Step title="Start a new trigger">
    In the sidebar, click the arrow next to **New session** (**More create options**) and choose **New Trigger**. Give it a **Name**.
  </Step>
  <Step title="Choose On Event">
    Under **Trigger**, choose **On Event**.
  </Step>
  <Step title="Find the event">
    Open the event list and type in **Search triggers…** — "pull request", "new row", or "Slack". Use **All integrations** to narrow the list to one app.
  </Step>
  <Step title="Pick the account">
    If you've connected more than one account for that app, choose which one the trigger should watch.
  </Step>
  <Step title="Fill in the settings">
    Most events have a setting or two to narrow them down — which Slack channel, which Notion database, which spreadsheet, which Gmail search to match.

    <Tip>
      Narrow the trigger as much as you can. A Gmail trigger scoped to one search is more useful, and cheaper to run, than one that fires on every incoming message.
    </Tip>
  </Step>
  <Step title="Choose the script">
    Under **Action**, choose **Run Script**, pick the script, and fill in any inputs it needs.
  </Step>
  <Step title="Create the trigger">
    Click **Create Trigger**. It starts watching straight away.
  </Step>
</Steps>

Or skip all of that and describe it in chat: *"Run this whenever a new row is added to the Q3 leads sheet."*

### Messages on your own accounts

The LinkedIn, WhatsApp, Telegram, and Instagram events watch **your own** account, linked as an integration. A script can then react to a new message, an edited message, or a reaction — and, on LinkedIn, a new connection. Message events can be limited to messages that contain certain text, and reaction events to one reaction.

Linking one of these accounts costs credits each month. See [Messaging accounts](/integrations/messaging-accounts).

<Note>
  LinkedIn reports a new connection late, so **new connection** can fire a few hours after the invitation was accepted.
</Note>

## How quickly a trigger fires

It depends on the app:

- **Instantly** — apps that notify Script.it directly the moment something happens. Slack, Stripe events, GitHub pull request events and pushes, Linear, Jira, Trello, Asana, Zoom, Shopify orders, and the LinkedIn, WhatsApp, Telegram, and Instagram message events work this way.
- **On a regular check** — for everything else, Script.it checks the app every 1–5 minutes, depending on the event, and runs your script when it finds something new. A trigger that has been quiet for a while checks less often, up to 15 minutes apart, and speeds up again after it fires.

While the script is open on your screen, its checking triggers run every minute, so you can test one and see it fire quickly. See [Checking right now](/triggers/managing#checking-right-now).

Either way you don't have to configure anything — each event already uses the fastest method its app supports.

## Messages to your agent

The channels you use to talk to your own agent run on triggers too. Connecting a channel adds its trigger for you, so you rarely add one by hand:

| Channel | Trigger it adds |
|---|---|
| [Email](/channels/email) | **Mail received** |
| [Slack](/channels/slack) | **Slack DMs** and **Slack Mentions** |
| [Microsoft Teams](/channels/microsoft-teams) | **Teams DMs** and **Teams Mentions** |
| [Telegram](/channels/telegram) | **Telegram DMs** |
| [WhatsApp](/channels/whatsapp) | **WhatsApp message received** |

The same events are in the **On Event** list — **Agent Email**, **Slack DM**, **Slack Mention**, **Teams DM**, **Teams Mention**, **Agent Telegram**, and **Agent WhatsApp** — along with **Telegram Bot DM** for a Telegram bot of your own.

Mail to your agent's own email address is accepted only from your own verified email address. A `+tag` address, like `you+support@…`, belongs to an External Agent, which anyone can write to. See [Reach your agent](/channels/overview) and [External Agents](/scripts/agents).

## What your script receives

When the trigger fires, the event's details are handed to the script — the message text, the issue title and body, the row that was added, whatever the app sent. Your script can read those values and act on them.

If the script produces files, they're available in that run's session, just like a run you started yourself.

## Managing app event triggers

Turn a trigger off and on from its card in the script, and check its **Recent runs** there too. See [Managing triggers](/triggers/managing) for run history, failures, and limits.
