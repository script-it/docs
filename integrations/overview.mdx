Integrations give your scripts access to the tools you already use. Script.it connects to 600+ apps, including Slack, Gmail, Notion, HubSpot, Airtable, Google Sheets, Linear, Jira, and Shopify. You can also link your own messaging accounts, add remote MCP servers, and create custom integrations for any REST API.

## What integrations are

An integration is either:

- **A connection**: an authorized account for an external tool, such as your Slack workspace, Gmail account, or an API key for an internal service.
- **An integration type**: the reusable definition of an API, such as its auth mode, base URL, and OAuth settings.

For built-in apps, Script.it provides the integration type, and you connect your account. For custom integrations and MCP servers, you or a teammate define the type, then each member can connect their own credentials through it.

When a script uses an integration, Script.it adds the authentication to each request. Scripts don't store API keys, OAuth tokens, or secrets in their files.

## How the AI agent uses integrations

When you describe an automation in chat, the agent works out which integrations it needs. If you say "send a Slack message whenever a new row is added to my Airtable base," the agent sees that it needs Slack and Airtable, uses the actions those integrations provide, and builds the script.

If a required integration isn't connected yet, the agent asks you to connect it during the session, so the automation can continue.

## Sharing integrations

You can keep integrations private or share them.

| Share type | What is shared | How runs authenticate |
|---|---|---|
| Shared connection | Your connected account and its credentials, with a workspace | Workspace members call the upstream API as you. |
| Shared custom integration type | The API definition only, with a workspace or with everyone in your company | Each person connects and runs with their own account. |

Sharing a connection authorizes the account, not just the workspace. Once shared, every member of that workspace can use the connection from their sessions and scripts. You can share the same connection with more than one workspace.

<Warning>
  Share connections only with people you trust. When members use a shared OAuth or API-key connection, upstream requests may appear as the connection owner in the provider's logs or audit trail.
</Warning>

Managing an integration is separate from workspace role. The creator can manage it, and editors can be added to a custom integration type. A workspace Editor who received an integration through a share can use it, but can't edit, rotate, or delete it.

## Controlling what integrations can do

Three controls decide whether a request through an integration goes ahead:

- **Integration policies**: limits set on a connection or a custom integration type by whoever manages it.
- **Integration calls**: limits your organization sets on a member or a role.
- **Permission profiles**: limits on what a session or an Agent may do.

All three apply to every call. See [Integration policies](/governance/integration-policies) and [Permission profiles](/governance/permission-profiles).

## How to get started

To use an integration in your scripts, connect it from **Settings → Integrations**. Search for the tool, click **Connect**, and complete the authorization flow.

For team workflows, open the integration's sharing controls and choose which workspaces can use it. See [Connect integrations](/integrations/connecting) for details.
