You work with your agent by chatting. Describe what you want in plain English — build a script, run it, fix a failure, add a step — and the agent does the work while you watch. Its replies stream in as it goes.

## Start a session

<Steps>
  <Step title="Open a new session">
    Click **New session** at the bottom of the sidebar, or press `Cmd+Shift+S` (`Ctrl+Shift+S` on Windows). The new session offers three starting points: **Guide me to automation**, **Teach me about Script.it**, and **Templates for common Scripts**. Click one to put its prompt in the message box, or to open the templates.
  </Step>
  <Step title="Describe what you want">
    Type in the message box and press `Enter`, or click the send button. Say what should go in, what should happen, and where the result should go.
  </Step>
  <Step title="Watch the agent work">
    A **Working** indicator shows above the message box while the agent is busy. When it finishes, its steps fold into a **Details** section you can expand. Scripts it created or changed appear as chips above the message box.
  </Step>
</Steps>

A new session isn't saved until you send its first message.

## The composer

The message box at the bottom of the session is the composer. Its placeholder reads **Ask anything, @ to reference**.

| Control | What it does |
|---|---|
| Permission selector | Shows the session's permission profile, **Full** by default. Pick another to limit what the agent may do. See [Permission profiles](/governance/permission-profiles). |
| Model picker | Shows the model the agent uses, **Auto** by default. See [Models](/sessions/models). |
| Microphone | Dictate your message. See [Dictate a message](#dictate-a-message). |
| **@** (**Reference Scripts, Files or Integrations**) | Opens the reference menu. You can also type `@`. |
| Paperclip (**Attach files**) | Attach files from your computer. |
| Send | Sends the message. While the agent works, a **Stop generation** button sits next to it. |

You can send another message while the agent is still working. To stop it, click **Stop generation**.

Above the composer, a row shows the **Working** indicator, chips for the scripts this session touched, and a folder button that opens [Session Files](/sessions/files).

## Reference things with @

Type `@` or click the **@** button to point the agent at something specific. The reference menu has two parts:

- **Used in session** — scripts this session already worked on. Click the arrow beside a script to pick one of its blocks.
- **Library** — browse **Scripts & Blocks**, **Integrations**, **Triggers**, **Files**, and **Sessions**.

Keep typing after `@` to search everything at once. A search also lists your permission profiles, under **Permissions**.

A reference becomes a chip in your message, so the agent knows exactly which script, block, file, or session you mean.

```
Run @weekly-digest with last month's dates
```

```
Compare the output of @fetch-orders with the file I attached
```

You can also drag a script or session from the sidebar onto the session to reference it.

## Attach files

Click **Attach files**, paste a file, or drag files anywhere onto the session. The composer shows **Drop to attach to your message** while you drag. Any file type works. Folders can't be attached; attach the files inside instead.

Attached files are saved in the session's [Session Files](/sessions/files) when you send the message, so the agent and your scripts can use them.

## Dictate a message

The microphone button turns speech into text in the composer. Dictation works on every plan, Free included.

- **Hold** the button to talk, and let go to stop.
- **Tap** it to start dictating, and tap again (**Stop dictation**) to finish.

The composer reads **Listening…** while it records. Your words appear in the message box, where you can edit them before you send.

<Note>
  Your browser asks for microphone access the first time. The button doesn't appear in browsers that can't record audio.
</Note>

## Build a script

Describe the automation you want. The more context you give, the better the first version.

```
Build me a script that fetches the latest 10 issues from our GitHub repo and posts a summary to Slack.
```

```
Create a script that downloads a CSV from a URL, keeps rows where "status" is "active", and saves the result as a new file.
```

```
Build a weekly digest that summarizes my unread Gmail and emails me the summary every Monday morning.
```

The agent writes the script one block at a time, running each block as it goes. The script opens beside the session so you can watch it take shape. You don't need to touch any files yourself.

<Tip>
  Start with one clear goal per script. Once the first version works, add steps, change logic, or connect more integrations one at a time.
</Tip>

## Run a script

Ask the agent to run it:

```
Run @weekly-digest
```

The agent starts the run, and each block's results show in the chat and on the script as they finish.

You can also run a script yourself from its page. See [Inputs and running](/scripts/inputs-and-running).

## Change a script

Once a script exists, refine it in conversation. Name the script or block, or just describe the change — the agent knows which script you've been working on.

```
Update the Fetch Issues block to also include the issue author and assignee.
```

```
Add a step after "Process Data" that uploads the output file to Google Drive.
```

```
The email block fails with a 401 error. Can you fix it?
```

## Undo a change

Script.it saves a version of a script at the end of every agent turn that changed it. To go back:

- **Restore it yourself.** On the script's page, click the history button beside **Run**, pick a version, click **Restore version**, and confirm with **Restore this version**. See [Outlines, comments, and history](/scripts/outline-and-history#history).
- **Ask the agent.** For example, "Undo that last change" or "Go back to the version before you added the Slack step."

## Rewind or edit the conversation

- **Rewind.** Hover one of your earlier messages and click the rewind button (**Rewind conversation here (files unchanged)**). The conversation goes back to that point. Files and scripts stay as they are.
- **Edit.** Click one of your earlier messages to edit it and send it again.

Both are unavailable while the agent is working.

## Read the agent's work

- **Working** — shown while the agent is busy. Its steps stream in as it reasons and uses tools.
- **Details** — when the agent finishes, its steps fold into a **Details** section. Expand it to see exactly what it did.
- **Reply** — the agent's explanation of what it did, or what you should do next.
- **Run results** — when a script runs, each block's result appears inline.

If a run fails, the agent shows the error and usually suggests or applies a fix.

Each of the agent's replies has a **Message options** menu with **Copy message** and **Credits used so far**, the credits this session has used up to that reply.

## Ask about other sessions

The agent can look through your earlier sessions in the same account. Ask it things like "What did we decide about the invoice script last week?" or "Find the session where I set up the Slack trigger." You can also reference a session with `@`.

## Tips for effective prompts

- **Be specific about inputs and outputs.** Instead of "process the data," say "read `report.csv`, keep rows where `revenue` is over 1000, and save the result to `filtered.csv`."
- **One change at a time.** Focused requests give more predictable results.
- **Reference what you mean.** With several scripts, use `@` to point at the one you mean.
- **Describe the goal, not the code.** Say what you want to achieve and let the agent choose how.
- **Iterate.** If the first version isn't right, say what's missing or wrong.

## Reach your agent outside the app

You can also message your agent by email, Slack, Teams, Telegram, or WhatsApp. Each conversation is a session you can open here. See [Ways to reach your agent](/channels/overview).
