Every script is made up of blocks: the steps that run, in order, when the script runs. Each block does one thing, such as fetching data, writing a summary, or sending a message. Together they form the automation.

## Kinds of blocks

| Kind | What it does |
|---|---|
| **Code block** | Runs code to do a step: call an API, process a file, send a message. Most blocks are code blocks. |
| **Agent block** | A code block that hands its step to an AI Agent with its own instructions and permission. See [Agents in scripts](/scripts/agents). |
| **Block with nested blocks** | Runs the blocks inside it, once for each item in a list or in sequence. The nested blocks show inside its card. |
| **Markdown** | Text that explains the script. It doesn't run. |
| **Prompt** | A button inside Markdown text that sends a prompt to the agent. It doesn't run with the script. |

A script's [triggers](/triggers/overview) also appear in it, as cards beside its blocks.

## Code blocks

A code block runs a source file, usually Python. The agent writes the code for you, and the block's card explains what it does in plain language, so you rarely need to read the code itself. To see it, choose **View Source** from the block's **⋮** menu.

A block can take inputs, use your connected integrations, read [script assets](/scripts/assets), and use what earlier blocks produced. The files it writes become its outputs.

Each block has its own output folder. It's normally cleared before the block runs again, so a rerun doesn't mix old and new results.

## What a block card shows

Click a block to open its card. From top to bottom, a card shows:

- **Name and description.** The block's name, the icons of the integrations it uses, and what it does.
- **Block inputs.** The values that change how the block behaves each run. See [Inputs and running](/scripts/inputs-and-running).
- **Assets.** Files the block reads from the script's assets.
- **Dependencies.** The outputs this block pulls from earlier blocks.
- **How this block works.** The block's steps in plain language. See [Outlines, comments, and history](/scripts/outline-and-history).
- **Outputs.** What the block produced in its latest run in this session.

A block that waits, ends the run early, or runs an Agent has a mark beside its name. Point at it to see what it waits for or when it can end the run.

## Block outputs

When a block has run, its outputs appear at the bottom of its card. A bar across the top of the outputs holds:

- **Timeline.** The block's progress, step by step, with its log lines. Use it while the block runs and to find where a failure happened.
- **File chips.** One chip for each file or folder the block wrote. Click a chip to show that file. Click a folder to open it.
- **Annotate.** For JSON and CSV files, spreadsheets, and HTML pages: lets you click a value, a cell, or an element and comment on it.
- **Open file in popup.** Opens the file in a larger view.

When a block has run more than once in the session, a bar above lets you pick the run to show.

If the block failed, its card shows **Show error details** and a prompt that asks the agent to fix it. Click the prompt to send it.

<Note>
  Outputs are stored in the session, not the script. The same script can run in many sessions without the outputs mixing. If a file should stay with the script, keep it as a [script asset](/scripts/assets).
</Note>

## How results look

The agent shapes each block's outputs so you can check them at a glance.

- **A summary first.** A file named `output`, such as `output.md` or `output.html`, opens first and acts as the block's summary.
- **Interactive HTML.** HTML files render as live pages, with scripts and forms working.
- **Data you can edit.** JSON files open in JSON Views, as tables, record pages, Kanban boards, or custom layouts. CSV files open as tables.
- **Documents and media.** PDFs, images, audio, video, Word documents, Excel workbooks, and PowerPoint decks open in place.

Ask for the presentation you want: "Show the leads as a Kanban board by status", or "Write a one-paragraph summary as the block's output".

### Cover and theme

A script's header has a cover: an animated theme generated from the script, or an image. Click **Edit cover** to pick a theme, adjust its color, or use your own image. You can also ask the agent to change it.

## Markdown and prompt blocks

Markdown blocks hold the script's documentation: its purpose, what it needs, and notes for teammates. Double-click Markdown text to edit it in place. To add one, choose **Add Markdown Below** from a block's **⋮** menu.

Markdown can also hold **prompt blocks**: buttons that send a prompt to the agent, which you can edit before sending. They suit templates and shared scripts, such as a "Customize this for my team" button. Ask the agent to add one.

## Block actions

A block's **⋮** menu offers:

| Action | What it does |
|---|---|
| **Run block** | Runs only this block |
| **Reference block in chat** | Adds a tag for the block to your message, so the agent knows which block you mean |
| **Open full view** | Shows the block alone, in full, in place of the script |
| **View Source** | Shows the block's code |
| **Explain this block** | Asks the agent to write the block's outline, when it has none |
| **Rename** | Renames the block |
| **Add Markdown Below** | Adds a Markdown block after this one |
| **Delete Block** | Removes the block from the script |

Some actions need edit access to the script's workspace.

## Changing blocks through chat

The agent creates and maintains the blocks for you. Describe the change you want in plain language.

<Steps>
  <Step title="Adding a block">
    Describe the new step: "Add a block that reads a CSV file and keeps only rows where the status is 'active'." The agent writes the code, adds the block in the right place, and runs it to check it works.
  </Step>
  <Step title="Changing a block">
    Describe the change, or [comment](/scripts/outline-and-history#commenting-on-a-script) on the block's outline: "Also include the author field." The agent updates the code and the outline together.
  </Step>
  <Step title="Removing a block">
    Ask the agent: "Remove the email notification step." The agent removes the block and updates the script.
  </Step>
</Steps>

## Reviewing a script

The script page shows blocks in the order they run. For a weekly report script, you might see:

- **About this script.** A Markdown block that explains the goal and what the script needs.
- **Fetch report data.** A code block that collects the latest data.
- **Write the summary.** An Agent block that reads the data and writes a short report.
- **Approve and post to Slack.** A code block that asks you to approve the report, then posts it to the right channel.

Open a block to review what it does and its latest results, or ask the agent to change it.
